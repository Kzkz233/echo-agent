# 渠道与表达

[文档](README.md) / 渠道与表达

## 对话与投递

在 Echo 里和伙伴说过的话，可以在绑定的 QQ 上接着聊。伙伴也可以在桌宠气泡里回应你。通知收件箱用于查看通知和任务结果。

在伙伴的 **通道与表达** 中，可以分别设置她在各处的说话风格。设置任务时可以选择在哪里收汇报。**聊天** 页显示伙伴实际发来的消息。要看她查了什么、用了哪些工具，打开 **后台工作会话**。

模型可以在一次交付中提供多条消息，也可以先发送简短进展、继续处理，再发送结果。应用聊天和 QQ 支持分条呈现及发送间隔，具体分段仍受渠道限制约束。

## 聊天文件

应用聊天支持选择、粘贴或拖入文件，每条消息最多 4 个，每个不超过 8 MB。发送后，自己的气泡立即显示。桌面端点击文件名可在资源管理器中查看交付版本；浏览器端点击下载。普通文档保留原件，有项目目录时为本轮输入准备工作副本。图片和短文本沿用模型的图文输入。

伙伴可以把本次聊天的附件交给子任务。子任务做完后，可以把生成的文件交回给伙伴，再发到 Echo 的聊天里供你打开或下载。QQ 支持接收图片。

## 连接 QQ

1. 在 **设置 → 扩展** 中启用 QQ 机器人连接功能，填写机器人的 App ID 和凭据。
2. 在渠道设置中，把 QQ 联系人绑定到要聊天的伙伴。
3. 在伙伴配置中设置她在 QQ 上的说话风格。需要任务提醒时，在该任务里选择对应的 QQ 联系人。

同一个外部联系人最多有一个有效绑定。新联系人完成绑定后才能触发伙伴执行。回复通常返回来源渠道，任务汇报使用任务预先选择的目标。主动推送还需满足 QQ 平台权限。

QQ 使用官方网关和 REST 接口。网关连接由插件管理，心跳超时后重连。文字与图片的发送序号、消息 ID 和回执分别记录。分段数量和长度受平台限制，无法容纳的首选分段会按发送预算调整。

## 聊天表情

启用聊天表情插件后，可为伙伴添加表情图片、说明和使用偏好，并按渠道选择是否启用。渠道通过注册信息声明图片支持情况，不支持图片的目标不可启用表情。

符合条件的交流会注入表情目录与可用目标。模型选择的图片由 Files 解析为受保护的附件，再由渠道适配器呈现。当前表情适用于用户交流和主动交流，屏幕观察气泡使用文字。

## 任务汇报

任务结果先记录到伙伴主工作会话。开启 **汇报结果** 后，父会话准备汇报并调用渠道投递工具。关闭汇报时保留结果，不唤醒父会话。

任务保存所选渠道、联系人和绑定版本。主会话准备汇报时，Echo 按当前权限和状态核对这些目标，发送前再核对一次。补跑和断点续跑沿用同一套核对流程。渠道恢复后可以接收尚待汇报的结果；联系人被替换或授权被撤销时，原目标会被跳过。通知收件箱是独立投递目标，其表达风格与聊天分别配置。

## 发送回执

运行记录区分已受理、排队、已投递、失败和结果未知。服务端接受请求与用户实际看到消息是不同状态。桌宠气泡在渲染后确认显示。

确定失败的发送可从记录中重试，已确认的部分不会重发。结果未知的发送需要核对或明确关闭记录。关闭记录不撤回远端已接受的消息。

## 扩展接口

Channels 管理入站与绑定，Deliveries 管理出站。渠道插件通过版本化注册表提供目标，前端从同一注册信息生成配置项。

| 接口 | 内容 |
| --- | --- |
| `core.outputs.targets@1` | 投递目标、版本、可用状态、展示能力，以及幂等 deliver 和只读 inspect |
| `channels.image-adapters@1` | 外部渠道图片发送能力 |
| `channels.availability@1` | 适配器可按伙伴、会话、联系人和是否回复来检查当前发送权限。查询不发送消息。 |
| `outputs.provide` | 注册投递目标所需的插件权限 |

任务保留所选目标的插件、绑定标识和版本。插件稍晚启动时，Echo 可用本机登记过的目标标识找回原联系人。可用状态和发送权限在汇报时重新读取。修改绑定的联系人后，需要在任务中重新选择目标。

绑定采用 `(adapter, peer) → conversation`。入站消息按远端消息 ID 去重，经过公共输入队列提交。渠道来源不构成审批权限。

Agent 交付使用 `echo_respond`。允许静默的调用方可提供 `echo_silence`，在尚未开始回复时结束当前交互。普通模型文本不自动转发。工具选择策略遵循对应模型协议的限制，完成检查在公共管线执行。

会话持久化保留原生工具调用与结果，渠道消息是展示投影。历史恢复不会执行旧工具或重新发送消息。来源与时间信息作为消息元数据进入上下文，过去的任务记录保持其应用数据属性。

插件停用会释放连接、定时器和待执行工作，绑定与历史记录保留。伙伴包导入后需重新确认本机渠道与投递目标。
