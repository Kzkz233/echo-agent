# 发布规范

[文档](README.md) / 项目维护

## 版本与内容

Git 标签使用 `vMAJOR.MINOR.PATCH`，版本与 package.json、桌面配置及 Rust 包保持一致。发布标题统一使用 `Echo Agent <版本>`，正文开头概括本版主题。

发布说明保存在 `docs/releases/<版本>.md`。按需要使用以下章节，省略空章节。

| 章节 | 内容 |
| --- | --- |
| 开头摘要 | 一至两句话说明本版重点 |
| 新增 / 改进 / 修复 | 按用户操作描述变化，每条一个事实 |
| 升级说明 | 需要用户执行的操作、兼容要求或迁移影响 |
| 已知问题 | 已确认且会影响使用的问题与可用处理办法 |
| 下载 | 安装包、更新包、源码和校验文件的用途与链接 |

接口名、实现经过和详细测试输出保留在技术文档或验收记录中。每版发布说明聚焦本次变化，通用升级与备份步骤链接到更新指南。

发布正文可参考 [0.21.1](releases/0.21.1.md)，编写时使用 [模板](releases/TEMPLATE.md)。

## 准备

1. 确认工作树与发布版本，提交本次变更。
2. 运行 `pnpm verify`，并完成修改范围对应的原生与界面检查。
3. 完成版本说明，检查标题、下载名称和升级要求。
4. 使用维护者本机的发布策略运行 `pnpm release:public`。

发布策略由 `ECHO_RELEASE_POLICY` 指定，默认位于用户目录的 `.echo/echo-release-policy.local.json`。它记录公开仓库、私有参考目录、工具路径、排除规则与批准媒体指纹。维护者在仓库之外保管该文件。

准备脚本检查已提交源码、未发布提交、安装程序和更新包，验证插件范围、凭据特征、私有参考与媒体清单。通过后生成安装包、更新包、源码包、SHA-256 清单和本地验收记录。

## 发布

发布获授权后，执行 `pnpm release:publish`。脚本重新检查产物与提交的一致性，推送 main 和版本标签，上传文件，并核对 GitHub 返回的文件摘要。

发布后检查最新版本入口、正文、文件名和下载链接。用户通过应用内检查更新或下载安装程序升级。

[更新与恢复](UPDATES.md)

## 修订已发布说明

文案纠错先修改对应 Markdown，再使用 `gh release edit <tag> --notes-file <file>` 同步。标题可用 `--title` 更新。文档修订提交到 main，发布标签和二进制仍对应原始构建。

如果程序或安装文件发生变化，使用新版本重新构建和验证。历史 Release 的说明保留该版本当时的功能范围。
