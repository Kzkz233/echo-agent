# 0.18.3

Memory Review now checkpoints candidates after each material packet. Resume keeps the
saved candidates and confirmed changes; pending candidates must be resolved before
completion. Raw packets remain in the job archive instead of being copied into the
canonical worker history on every read.

Agents receive paginated memory summaries and can search related memories through
the registered retrieval provider. Maintenance search is independent of chat recall
suppression. Updating or merging a memory in Review requires reading its complete
current version. Tags and optional occurrence dates are supported by versioned tools.

Review tasks can optionally maintain a batch of the existing memory library. The
cursor advances after successful completion. Existing tasks remain incremental;
there is no new automatic maintenance policy, forgetting curve or permission grant.

Failed model requests retain content-free transport diagnostics. Review progress
queries no longer return historical frozen prompts and drafts to model tools.
Completion archives and parent reports separate the model's reading summary from
confirmed memory changes and registered plugin acknowledgements.
Reply tools clarify that final delivery is submitted once per target, with all
message parts in one array. An explicit report verification can target a subset
of its original destinations without repeating memory work or completed channels.

Existing persona text, memory bodies, schedules, authorization, external extensions
and credentials are preserved. Completed work continues to report through the
parent session and its configured delivery targets.
